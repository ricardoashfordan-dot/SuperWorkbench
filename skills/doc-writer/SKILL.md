# 项目文档编写

## 确立文档目标

- 先确认目标读者、他们已有的背景和读完后应该能做的操作。
- 阅读项目现有文档、入口、配置和测试，再核对技术事实。
- 把概述、日常操作和维护细节按读者任务组织。
- 保留已有术语和约定，引用仓库中的实际文件和配置项。

## README

- 开头用一段话说明项目解决的问题、适用读者和主要入口。
- 列出运行要求、安装方法和一个可执行的最小示例。
- 标注工作目录、需要提前准备的环境和成功时能看到的结果。
- 为常见错误给出可诊断的症状和对应解决方法。
- 把深入配置、开发贡献和设计说明放在各自的章节。

## 变更说明

- 以使用者看到的行为描述改动，补充受影响的版本和平台。
- 标明迁移步骤、兼容行为和需要手动操作的事项。
- 按新增、修复和行为变化归纳本次内容。
- 引用可信的提交、测试或复验记录支撑重要结论。

## 架构文档

- 从模块职责、数据流和边界入手，再展开关键调用链。
- 描述读写的数据、状态由谁持有，以及失败和重试时怎样处理。
- 记录设计取舍和影响维护的约束，示例使用仓库相对路径。
- 短图使用源码中的真实模块名称，确保箭头方向与调用关系一致。

## 发布前核对

- 验证命令能从标注的工作目录执行，名称和链接能在仓库中找到。
- 检查截图和示例输出是否来自实际运行或明确标注为示意。
- 确认版本、参数和配置默认值与源码一致。
- 省略密钥、凭证和个人路径。
- 在交付中注明哪些步骤已实测以及哪些有待读者确认。
