# 证据绑定代码审计规范（Evidence-Bound Review）

审查任何代码变更或方案时，必须遵守以下铁律：

1. **证据绑定原则**：
   - 每一条问题必须明确指出具体的 **文件路径 + 函数/行号范围**，严禁空泛地说“这里可能有问题”。
2. **按严重程度分级输出**：
   - **P0（阻断级）**：崩溃、数据丢失、死锁/竞态、安全漏洞或硬编码私密信息；
   - **P1（高优修复）**：显著性能卡顿、边界条件漏判、资源泄漏；
   - **P2（可维护性建议）**：重复代码、命名不清、缺少错误提示。
3. **给出可直接落地的最小修改方案**：
   - 对每个 P0/P1 问题，附带简短明确的修复代码片段与验证方式，避免过度重构。
