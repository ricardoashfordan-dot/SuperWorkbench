# 缺陷定位

## 固定现象

- 用一句话写清预期行为、实际行为和受影响的人或流程。
- 记录发生问题的版本、配置、输入和可观察输出。
- 用最少操作复现，保存干净的错误片段及触发用例。
- 间歇问题记录触发频率和与并发、网络、时钟相关的条件。
- 对无法重现的问题保留证据，指出当前缺少哪个条件。

## 缩小范围

1. 比较一个正常用例和一个失败用例，每次只改一个变量。
2. 从用户入口沿调用链跟到首次出现异常的模块。
3. 区分数据问题、状态问题、环境问题和实现问题。
4. 缩小输入，直到再删减就无法触发同类故障。
5. 如需隔离外部服务，用可控替身保留相同的输入和返回契约。

## 验证根因

- 写出可验证的假设，说明它预测的具体输出。
- 检查导致故障的第一次状态偏差，记录位置和触发条件。
- 解释为何相似用例正常，排除会给出相同表象的替代解释。
- 记录证据能支持到哪一层，保留仍需核实的环节。

## 修复和回归

- 从最小修复开始，按原入口验证行为。
- 用失败用例建立回归检查，再覆盖相邻边界和正常场景。
- 对涉及持久化或失败重试的操作，检查同一输入再次提交的结果。
- 涉及旧数据时，至少用一份旧格式样例验证兼容。
- 运行相关测试，准确记录通过、失败或无法运行的原因。

## 交付

- 给出复现步骤、根因、改动位置和验证结果。
- 说明修复覆盖的场景与仍可观察的风险。
- 保留可复制的最小输入和预期输出，方便下一位维护者复验。
