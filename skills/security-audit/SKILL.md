# 应用安全审查

## 开始前

- 确认需要审查的应用、代码范围、运行环境和信任边界。
- 从路由、任务入口和外部调用绘出输入到敏感操作的短链路。
- 标出用户身份、数据归属、敏感数据、文件写入和出站请求。
- 默认以源码和现有测试为证据，对需要环境验证的结论注明条件。
- 使用脱敏的请求字段、文件名和日志片段描述问题。

## 检查顺序

1. 鉴权与授权
   - 核对每个敏感入口是否执行会话验证和对象归属检查。
   - 比较读取、更新、下载和后台任务是否执行相同的权限约束。
   - 核对无凭证、凭证失效和权限不足时是否一致地拒绝。
2. 注入与不可信输入
   - 跟踪外部输入进入数据库、命令参数、模板以及模型工具的路径。
   - 优先检查参数化、数据类型约束和命令与参数的分离。
   - 核对错误处理是否保留防护，重试是否会走不同的执行路径。
3. 路径穿越与符号链接
   - 核对最终解析路径位于允许的目录，写入和删除也应使用同一规则。
   - 检查导入、导出、静态文件和附件访问是否遵守各自的目录边界。
4. SSRF 与重定向
   - 核对允许的协议、目标、端口、逐跳校验和超时是否同时生效。
   - 检查响应大小与失败回退行为，确认出站请求使用预期的凭证范围。
5. 密钥和隐私
   - 检查日志、构建产物、错误回包和导出文件是否暴露敏感字段。
   - 记录密钥的用途和存放边界，报告里仅引用变量名或脱敏标识。

## 交付

- 按影响和可达性排序，列出证据、影响范围及最小修复建议。
- 区分已由源码证明、需要配置核实和已有测试覆盖的结论。
- 为关键修复提供防御性回归检查，重点验证拒绝路径和允许的正常操作。
- 说明哪些入口已经检查以及哪些部署条件仍待核实。
- 结束前确认报告里没有密钥原文、个人路径或无关用户数据。
